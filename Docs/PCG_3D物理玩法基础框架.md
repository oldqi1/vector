# PCG × 3D × 物理玩法基础框架

> 状态：长期基础合同。不会因单次 Demo 排期、怪物替换或 Boss 调参而废止。
> 作用：保证项目扩内容时仍然是“程序生成的 3D 物理战斗机器”，而不是随机房间、平面刷怪或专属机关谜题。
> 当前产品范围见 [`冲量荒原_Demo系统设计_v0.6.md`](冲量荒原_Demo系统设计_v0.6.md)。

---

## 1. 四条不可删除的基础合同

1. **确定性生成**：同一版本、同一 Seed 和同一输入生成同一模块序列与战术数据，失败原因可记录、可复现。
2. **房间是战术电路**：每个遭遇模块至少声明 Source、Converter、Receiver、Recovery，并存在两条首操作不同的 Recipe。
3. **3D 改变结果**：相对高度必须改变可命中关系、运动路径、结构响应或接收结果；仅增加楼梯、行走距离和视觉层次不算 3D 玩法。
4. **统一物理事实**：敌人、弹体、工具和场地装置只读取位置、速度、质量、法线、约束、摩擦、重力和结构状态，不识别“正确工具名称”。

若删除装置、敌人功能槽或 Z 轴后，玩家路线基本不变，则该模块不得进入正式候选池。

## 2. 房间最小语法

```text
Source 动能源
  → Converter 改变方向、轴、约束、摩擦或落点
  → Receiver 接受碰撞、坠落、结构事件或怪群连锁
  → Recovery 为失败后的重新设局提供安全空间
```

### Source

- 玩家主动矢量注入；
- 角槌兽冲锋；
- 弱追踪/扇形实体弹；
- Boss 冲撞或动能球；
- 高差、重力喷口、移动重物。

### Converter

- 斜面、硬墙、回弹面；
- 绳线锚点与双体约束；
- 升空叉和通用环境换向器；
- 低摩擦路径；
- 可改变路径的敌人结构。

### Receiver

- 怪群或大型目标结构点；
- 硬墙/裂解面；
- 下层落地区与 LandingShock；
- Boss 外壳或暴露核心；
- 可破坏接收器。

### Recovery

- 不被出生怪、门或环境装置封死；
- 玩家能观察下一次预警并重新选择 Source；
- 敌人和玩家掉入虚空后有确定的账本/重生结果；
- 不允许唯一安全区同时成为敌人出生点。

## 3. 当前代码数据合同

`FVectorTacticalModuleDefinition` 是当前模块事实源，保留以下字段：

| 字段 | 责任 |
|---|---|
| `ModuleId / Type` | 稳定身份与模块类型 |
| `Opportunities` | 长发射线、硬墙、怪群、冲锋诱导、绳线弧、高差、低摩擦、恢复区等机会位 |
| `EnemyBudget` | 敌人数预算，不等于随机散布数量 |
| `HeightLayerCount / MaximumHeightDifferenceCm` | 真实高度层和最大高差 |
| `Sources[]` | 可供给运动预算的角色/装置 |
| `Converters[]` | 可改变运动事实的角色/装置 |
| `Receivers[]` | 接收物理兑现的目标 |
| `RecoveryPockets[]` | 安全复位空间 |
| `SupportedToolVerbs[]` | 房间支持的玩家动词，不作为伤害白名单 |
| `EnemyFunctionalSlots[]` | Source / Ammunition / Receiver / Interference 等功能槽 |
| `Recipes[]` | 至少两条可解释链路 |
| `RewardBias` | 利用房间电路后的奖励倾向，不直接改变物理规则 |

当前确定性布局保留：

- `RequestedSeed / ResolvedSeed`；
- 最大 16 次派生 Seed 重试；
- `TacticalScore`；
- 验证失败原因；
- 已验证回退布局；
- 模块序列文本摘要。

UE PCG 或其他程序化工具可以负责植被、碎石、远景和不影响裁决的装饰；关键墙面、通道、高差、接收器、出生槽和 Nav 连通仍必须由可验证模块合同控制。

## 4. 3D 硬合同

### 地图

- 正式路线至少有一个无法压平成同打法的高度模块；
- 高层和低层都必须有功能角色，不能只有观景台；
- 高差配套动能源、转换手段、接收区和恢复路径；
- 落点预测必须检测墙、斜坡、平台、天花板和实际碰撞体。

### 怪物

- 至少一种敌人提供可利用的垂直或弹道运动；
- 高层敌人不是单纯让玩家多走楼梯，而是改变落点、视线或接收关系；
- 空中/高处应对来自真实几何与轨迹，不使用“只接受某工具”免疫；
- 敌人的攻击既是威胁，也是玩家可重新定向的物理材料。

### 工具

- 矢量枪：玩家最可靠的主动水平速度供给；
- 升空叉：水平→垂直轴转换与一次空中砸落；
- 绳线：三维约束、共同质心、角动量和后续高处移动；
- 物性工具：改变摩擦、有效重量或接收稳定性；
- 任一工具独自高效完成 Source→Converter→Receiver 全链，视为职责失败。

### Boss

- Boss 不免疫统一推力、约束、落地和结构事件；
- 可以通过质量、锚定、摩擦和离散结构改变响应；
- Boss 攻击必须持续产生有限、可操作的物理材料；
- Boss 房复用普通房已经教过的物理动词，不临时引入工具白名单。

## 5. 生成与运行时顺序

```text
Seed
→ 选择 SafeStart
→ 选择 2 个战术遭遇模块
→ 验证机会、两条 Recipe、高度和恢复区
→ 按功能槽填充敌群
→ 放置 BossRing 与 Extraction
→ 构建/验证 Nav、门、检查点和虚空回收
→ 输出布局与电路摘要
→ 进入房间后才激活对应遭遇
```

运行时必须保证：

- 波次门不切断 NavMesh；
- 出生点先投影到 Nav，失败有明确日志和安全回退；
- 弹丸、器官和环境 Actor 不进入敌人 remaining；
- 虚空击杀照常结算死亡、掉落和清房；
- 玩家虚空回收不修改遭遇账本；
- Boss 波次必须生成 Boss 本体，不能只生成 Adds；
- 房间完成后检查出口确实可通行。

## 6. 模块验收

每个新模块进入候选池前必须通过：

1. **电路完整**：Source/Converter/Receiver/Recovery 均非空；
2. **双路线**：至少两条 Recipe，首操作不同；
3. **敌人功能**：至少一个 Source 槽和一个 Receiver 槽；
4. **装置复用**：至少一个装置可被两种物理来源利用；
5. **3D 删除测试**：压平高度后至少一条高价值路线消失；
6. **装置删除测试**：删除关键 Converter 后至少一条路线消失；
7. **保底路线**：当前构筑仍能较慢完成主合同，不软锁；
8. **导航与边界**：无接缝卡怪、门切路、出生坠落或不可回收虚空；
9. **确定性**：同 Seed 双跑模块序列与稳定数据一致；
10. **玩家可读**：入口能在攻击前辨认主要动能源、转换方向和接收目标。

日志 PASS 不能替代第 10 条玩家验收。

## 7. 当前模块职责

| 模块 | 核心题目 | 必须保留的差异 |
|---|---|---|
| `SafeStart` | 观察与操作入口 | 无敌人缓冲、操作提示、恢复点 |
| `OpenBowl` | 长距离注能与怪群接收 | 开放发射线、侧向转换、非最近墙唯一解 |
| `HardLane` | 冲锋诱导与硬面兑现 | 直线 Source、侧向躲避口、第二转换路线 |
| `HeightShelf` | 水平动能换 Z 与落点兑现 | 多高度层、环境/工具两条换向路线、低层接收区 |
| `SlickCross` | 摩擦改变路线长度和交叉时机 | 低摩擦主轴、稳定接收者、安全干区 |
| `BossRing` | 综合考试 | 循环弹药、结构响应、恢复外环、无工具免疫 |
| `Extraction` | 结算 | 不再生成战斗威胁，账本锁定且可重复保护 |

模块可以改变几何位置、入口方向、敌群功能配方和奖励倾向；不得随机关键物理阈值、碰撞公式或工具语义。

## 8. 扩展纪律

- 先手工验证一个战术电路，再数据化进入 PCG；
- 新敌人必须改变目标优先级、站位、工具顺序或接收者；只改模型/血量不算新怪；
- 新装置至少服务两种 Source，或一种 Source + 一种敌人攻击；
- 新成长改变连接、转换或触发方式，不永久淘汰旧数值；
- 新 Boss 只主考一个物理概念并复习一个旧概念；
- 任何内容导致纯水平推墙、纯枪磨血或专属机关成为唯一解时，暂停扩内容并修基础电路。
