# 第一批 · 配置层（已完成文件改动）

## 已经改了什么

### 改动 1：`Vector/Config/DefaultEngine.ini`

| 项 | 改动前 | 改动后 | 为什么 |
|---|---|---|---|
| `r.RayTracing` | True | **False** | 成本随动态刚体数量增长，而本项目全场都在动；俯视平涂下可见收益≈0 |
| `r.RayTracing.RayTracingProxies.ProjectEnabled` | True | **False** | 同上，且会额外生成常驻代理数据 |
| `r.Substrate` | True | **False** | 多层材质系统，但材质是三色平涂无层可分；还会让第三方素材材质路径不一致 |
| `r.ReflectionMethod` | 1 (Lumen) | **0** | 平涂无镜面，反射贡献≈0 |
| `r.DefaultFeature.AutoExposure` | 未设（默认开） | **False** | 自动曝光会让地面明度随镜头变化，破坏明度分层 |
| `r.DefaultFeature.AutoExposure.Method` | 未设 | **2**（手动） | 同上 |
| `r.DefaultFeature.MotionBlur` | 未设（默认开） | **False** | 动态模糊与「读落点」直接功能冲突 |
| `r.SeparateTranslucency` | 未设 | **1** | 影子 Quad 和落点环需要稳定的半透明排序 |
| `r.GenerateMeshDistanceFields` | True | **True（不变）** | Niagara 的 Distance Field Collision 依赖它，不能关 |
| `r.Shadow.Virtual.Enable` | 1 | **1（不变）** | VSM 留着做氛围阴影 |
| `r.DynamicGlobalIlluminationMethod` | 1 (Lumen) | **1（暂不变）** | 属风格取舍，等你裁决，见下方「待你决定」 |

文件里每一项都加了中文注释，以后你自己看也能懂为什么这么设。

### 改动 2：`Vector/Vector.uproject`

启用了 Niagara 插件。改动前 `Plugins` 数组只有 `ModelingToolsEditorMode` 一项。

**这是个真实的排期缺口**：你的美术工时表里排了 2.5 小时做「矢量枪弹道、绳线、动能球撞击」的 Niagara 特效，但插件没开，那 2.5 小时在原状态下根本无法开始。

JSON 合法性已用 Python 验证通过，插件列表现为 `['ModelingToolsEditorMode', 'Niagara']`。

### 改动 3：新建 `Vector/Config/DefaultScalability.ini`

原本这个文件**不存在**，意味着没有 Low / Medium / High 画质档位。

后果不只是「玩家没画质选项」。更实际的问题是：你在 RTX 4070 笔记本上跑得动，不代表试玩者跑得动。而这是**定向机制验证包**——如果试玩者那边帧率崩了，他会把卡顿误判成「手感不好」，你就收到了错误的反馈。

新文件含 24 个档位段，覆盖 ViewDistance / Shadow / Effects / PostProcess / Texture / AntiAliasing 六类，每类 4 档。

其中一条纪律：**`r.MotionBlurQuality=0` 在全部 4 档里都是 0**，不随画质变化。因为它不是画质选项，是功能开关。

## 现在你要做的 4 步

### 第 4 步 · 重启编辑器

1. **完全退出 UE 编辑器**——注意是整个关掉，不是只停 PIE。

   > 这里特别提醒，因为你有在 PIE 运行中直接改属性的习惯，那样改动不会持久。配置文件改动更是必须完整重启才读取。

2. 重新打开 `C:\workspace\Vector\Vector\Vector.uproject`

3. 如果弹窗问是否重新编译，选**是**

4. 右下角会出现 shader 编译进度条，等它走完归零

   预计 5–10 分钟。工程只有 14 个纯色材质，不会很久。

5. 如果又弹出「Niagara 插件需要重启编辑器」，再重启一次

### 第 5 步 · 验证配置真的生效

编辑器里按 `~` 键打开控制台，**逐行**输入并回车：

```
r.RayTracing
r.Substrate
r.ReflectionMethod
r.DefaultFeature.MotionBlur
r.GenerateMeshDistanceFields
```

期望返回值：

| 命令 | 期望值 | 如果不对说明 |
|---|---|---|
| `r.RayTracing` | **0** | 配置没读到，检查是否完整重启 |
| `r.Substrate` | **0** | 同上 |
| `r.ReflectionMethod` | **0** | 同上 |
| `r.DefaultFeature.MotionBlur` | **0** | 同上 |
| `r.GenerateMeshDistanceFields` | **1** | 这个必须是 1，是 0 就错了 |

> 输入命令名不带参数时，控制台会显示当前值。如果显示的是 `= 1` 而你期望 0，说明配置文件没被读取——回到第 4 步确认是否完整退出过。

### 第 6 步 · 确认 Niagara 开了

两种验证方式，任选：

**方式 A**：菜单 `Edit → Plugins`，搜索框输入 `Niagara`，看那一项前面的复选框是否已勾选。

**方式 B**（更快）：在内容浏览器空白处右键，菜单里应该出现 **FX** 分类，展开后有 `Niagara System`、`Niagara Emitter` 等选项。有它就成了。

### 第 7 步 · 跑一次 PIE

1. 打开 `L_Prototype05`（这是你的默认启动关卡）
2. 点 Play
3. 试一下：开枪、推怪、看物体落地
4. 控制台输入 `stat unit` 看帧时间

**重要预期管理**：这一步画面会变得**更暗、更平**。

这是正常的，原因有两个：
- 曝光从自动改成手动了，但还没有后处理体积去设定曝光补偿值
- 后处理体积是第二批的第 3 步才建

**所以现在不要根据画面好看不好看来判断这批改动的成败。** 这一步的验收标准只有两条：
1. 上面 5 个控制台命令返回值正确
2. PIE 能跑、玩法功能正常、没有报错

画面变好看是第二批的事。

## 待你决定的一项（我故意没改）

`r.DynamicGlobalIlluminationMethod=1`（Lumen 全局光照）**我保留没动**，因为这属于风格取舍，不是技术错误。

**如果保留 Lumen**：画面有现代感的间接光弹射，但空中高速目标的间接光会滞后、出现拖影——而那正是你要玩家读落点的物体。

**如果关掉（设为 0）** 换手工三点光：一盏方向光 + SkyLight + 一盏补光，明度**完全可控且确定**，不会因相机移动变化。画面会显得更「平」更风格化，像一张干净的插画。

我的专业倾向是**关掉**，理由是「可控性 > 真实性」，俯视 low-poly 本来就不追求物理正确的光。但这会明显改变画面观感，所以由你定。

想改的话就一行：

```ini
r.DynamicGlobalIlluminationMethod=0
```

## 修正记录 · Scalability 初版漏写 5 类（已补齐）

**这是我的疏漏，从日志里发现的。**

日志显示引擎启动时实际请求 **11 类**档位段：

```
ViewDistanceQuality  AntiAliasingQuality  ShadowQuality
GlobalIlluminationQuality  ReflectionQuality  PostProcessQuality
TextureQuality  EffectsQuality  FoliageQuality
ShadingQuality  LandscapeQuality
```

而初版 `DefaultScalability.ini` **只写了 6 类**，缺失 5 类：`GlobalIlluminationQuality`、`ReflectionQuality`、`ShadingQuality`、`FoliageQuality`、`LandscapeQuality`。

**后果**：缺失的类别会静默回落到引擎默认值。不报错，但等于这 5 类**没有档位控制**——低配机上该降的降不下来。这种问题不会在开发机上暴露，只会在试玩者那边表现为莫名卡顿。

已补齐，现为 **11 类 × 4 档 = 44 段**。补充部分的设计取向：

| 类别 | 处置 | 理由 |
|---|---|---|
| `GlobalIlluminationQuality` | 按档递进 Lumen 质量 | 控制的是质量而非开关；若后续裁决关掉 Lumen，本段自动失效无需删 |
| `ReflectionQuality` | **全档压最低** | 平涂无镜面，反射零收益；全档压低可防将来误开时悄悄产生成本 |
| `ShadingQuality` | 各向异性全档关闭 | 俯视平涂用不到 |
| `FoliageQuality` | 全档密度 0 | 当前无植被；保留段落是为了不回落到默认值 |
| `LandscapeQuality` | 全档保守 | 本项目用 PCG 模块而非 Landscape |

`r.MotionBlurQuality=0` 经复核仍在全 4 档保持为 0。

> **补齐后需再重启一次编辑器**才会读到新增的 5 类。可用日志确认：搜索 `Applying CVar settings from Section [GlobalIlluminationQuality@` 是否出现。

## 修正记录 2 · 两个 cvar 名写得不对（已修）

补齐后的日志审查又抓到两处我的问题。**都不影响功能，但会产生日志噪声，属于该清掉的技术债。**

### 问题 1：用了 UE 5.7 起废弃的 cvar 名

```
LogOutputDevice: Error: Using a deprecated (as of UE 5.7) CVar/Command:
'r.TranslucencyLightingVolumeDim'. It will be removed in the future.
Change all uses to 'r.TranslucencyLightingVolume.Dim' instead.
```

我在 `ShadingQuality` 四档里写的是 `r.TranslucencyLightingVolumeDim`，UE 5.8 的正确名是 **`r.TranslucencyLightingVolume.Dim`**（多一个点）。

注意这条在日志里的级别是 **Error**，不是 Warning。虽然引擎做了兼容仍能生效，但按官方说明「将来会被移除」——留着就是等着未来某次引擎升级后静默失效。已全部改为新名。

### 问题 2：写了模块未加载的 cvar

```
LogConfig: CVar [[landscape.RenderNaniteLandscape:1]] deferred - dummy variable created
```

`landscape.` 前缀的 cvar 属于 Landscape 模块。本项目用 PCG 模块搭场景，**不使用 Landscape 系统**，所以该模块未加载，引擎只能创建一个 deferred dummy 变量占位。

这不报错，但是无意义噪声。处理原则要说清楚：

- **段落必须保留** —— 删掉 `LandscapeQuality` 四段会让该类回落引擎默认，等于又回到「无档位控制」的老问题
- **但段内不写 Landscape 专属 cvar** —— 改用 `r.LandscapeLODBias`，它是渲染侧通用项，不依赖 Landscape 模块加载

### 修正后核对

| 检查项 | 结果 |
|---|---|
| 废弃名 `r.TranslucencyLightingVolumeDim=` 残留 | 0 处 |
| 新名 `r.TranslucencyLightingVolume.Dim=` | 4 处（四档齐全） |
| `landscape.RenderNaniteLandscape` 配置项残留 | 0 处（仅注释里提到一次，非配置） |
| 类别数 | 仍为 11 |
| 段落数 | 仍为 44 |

> 这两项修正同样需要重启编辑器生效。验证方式：重启后搜日志 `deprecated` 与 `deferred - dummy`，前者应不再出现 `TranslucencyLightingVolume` 相关行，后者应不再出现 `landscape.` 相关行。

**一条经验**：改完 Scalability 不要只验证「值对不对」，还要扫一遍日志里的 `deprecated` 和 `deferred - dummy`。前者说明用了旧名，后者说明写了未加载模块的 cvar——两者都不影响当下运行，但都是会在未来某个引擎版本咬人的债。

源文件：`C:\Program Files\Epic Games\UE_5.8\Engine\Config\BaseScalability.ini`

**查证结论 1：官方只定义 10 类档位，没有 LandscapeQuality。**

**查证结论 3：另外两个 cvar 名也是错的。**

### 方法论修正（这条比具体修复更重要）

**写 Scalability 配置不要凭经验猜 cvar 名，直接对照引擎的 `BaseScalability.ini`。**

具体做法：

```bash
# 1. 看官方定义了哪些档位类别
grep -o "^\[[A-Za-z]*Quality@" \
  "C:/Program Files/Epic Games/UE_5.8/Engine/Config/BaseScalability.ini" \
  | sed 's/@//;s/\[//' | sort -u

# 2. 看某一类官方段内到底写什么
awk '/^\[ShadingQuality@3\]/{f=1;next}/^\[/{f=0}f' \
  "C:/.../BaseScalability.ini"

# 3. 全量核对自己用的每个 cvar 是否存在于官方基线
grep -oE "^[a-zA-Z][a-zA-Z0-9._]*=" Vector/Config/DefaultScalability.ini \
  | sed 's/=$//' | sort -u | while read v; do
    grep -q "^${v}=" "C:/.../BaseScalability.ini" || echo "缺席 $v"
  done
```

前两轮我都是「日志报错 → 改那一条」，属于被动打补丁，改一轮冒一轮。第三步那个全量核对循环才是应该一开始就做的——它一次性抓出了剩下全部问题。

> 本轮修正需重启生效。验证：搜日志 `deprecated` 应无 Translucency 相关行，搜 `deferred - dummy` 应无 landscape 相关行。

LogConfig: Set CVar [[fx.Niagara.QualityLevel:3]]
```

这是编辑器默认行为——开发机通常跑最高档。**但这意味着你平时看到的画面和帧率，都是 Epic 档的结果。**


后续做性能验证时，必须手动切到 Medium / Low 实测，否则那份 Scalability 配置等于没验过。切换方式：编辑器菜单 `Settings → Engine Scalability Settings`，或控制台 `sg.EffectsQuality 1`（0=Low, 1=Medium, 2=High, 3=Epic）。

## 已知问题 · 与本次改动无关

日志里有 5 条这样的警告：

```
LogMaterial: Warning: Material /Engine/VREditor/TransformGizmo/Main.Main
             missing usage flag SkeletalMesh! Default Material will be used in game.
LogSkeletalMesh: Warning: Material with missing usage flag was applied to
                 skeletal mesh /Game/Prototype/Character/Robot/SK_Robot

**已核实这不是本次改动引入的**：改动前的日志 `Vector-backup-2026.08.17-13.29.03.log` 里同样出现 5 次，数量完全一致。

不是阻塞项，但建议在第二批的步骤 D 之后顺手处理：给 `SK_Robot` 换上你自己的 `MI_Enemy_*` 或 `MI_Tool_*` 实例，这个警告会自然消失，同时也省掉每次启动的重编译。

## 步骤 B · 建 MF_HeightReadability（30 分钟）

这是本方案里**唯一专门服务你 3D 核心判据**的技术件。你的判据要求「玩家必须读懂落点，并能主动制造或改变高度关系」——那高度就必须在材质层被编码成看得见的信号。

### B1. 创建

1. 进 `Content/Vector/Art/Materials/Functions/`
2. 右键 → `Materials` → **Material Function**
3. 命名 `MF_HeightReadability`
4. 双击打开

### B2. 建输入节点

在图表里右键搜索 `FunctionInput`，建 3 个，逐个在左下属性面板设置：

| 输入名 | Input Type | Preview Value | 用途 |
|---|---|---|---|
| `GroundZ` | Function Input Scalar | 0.0 | 当前区域地面基准高度 |
| `LayerStep` | Function Input Scalar | **650.0** | PCG 层间落差，就是你的 650cm |
| `FogTint` | Function Input Vector3 | (0.165, 0.176, 0.204) | L0 地面色 `#2A2D34` |

> `LayerStep` 默认值填 650，因为那是你 PCG 的实际层间落差。这个数字对上了，画面上的高度刻度才和玩法里的高度对得上。

### B3. 连接节点

按这个顺序建节点（右键搜索节点名）：

```
1. AbsoluteWorldPosition          → 取世界坐标
2. Mask (只勾 B)                  → 取 Z 分量（UE 里 Z 对应 B 通道）
3. Subtract                        → A 接上一步，B 接 GroundZ
   得到 RelativeHeight（相对高度）
4. Divide                          → A 接 Subtract，B 接 LayerStep
   得到「第几层」的小数形式
5. Frac                            → 接 Divide，得到层内位置 t（0~1）
6. Floor                           → 接 Divide，得到层序号 n（整数）
```

然后建 3 个输出（右键搜索 `FunctionOutput`）：

**输出 1 — HeightBand**
```
Floor 的结果 → Multiply (× 0.04) → FunctionOutput 命名 HeightBand
```
作用：每高一层，明度 +4%。让层与层在画面上有区分。

**输出 2 — ContactShade**
```
Frac 的结果 → Multiply (× 3) → Saturate → OneMinus
→ FunctionOutput 命名 ContactShade
```
作用：贴近地面处压暗，制造「接触感」。物体是不是真的落地了，一眼能看出来。

**输出 3 — LayerLine**
```
Frac 的结果 → SmoothStep (Min=0.96, Max=1.0)
→ FunctionOutput 命名 LayerLine
```
作用：层交界处一道细亮线，让 650cm 的落差**可数**，不是靠玩家猜。

### B4. 保存并检查

按 Apply → Save。左下 Stats 面板应显示约 **12 指令、0 纹理采样**。

**为什么这个比 Lumen 值钱**：Lumen 给你物理正确的间接光，但玩家读不出「这里比我高一层」。这个函数给的是可数的高度刻度——它是你七项量化判据里第 1、6、7 项能否成立的视觉前提。

## 步骤 C · 建 M_VectorMaster（45 分钟）

### C1. 创建

1. 进 `Content/Vector/Art/Materials/Master/`
2. 右键 → `Materials` → **Material**
3. 命名 `M_VectorMaster`
4. 双击打开

### C2. 设置基础属性

选中最外层的材质节点（图表里那个大节点），左下 Details 面板：

| 属性 | 值 | 理由 |
|---|---|---|
| Shading Model | `Default Lit` | 需要接收方向光的明度分层 |
| Two Sided | 不勾 | 省一半渲染 |
| Blend Mode | `Opaque` | 影子 Quad 才用 Translucent，主材质不用 |

### C3. 建参数节点

右键搜索建这几个参数，**每个都要在 Details 里勾 Parameter Name**：

| 节点类型 | Parameter Name | 默认值 | 说明 |
|---|---|---|---|
| VectorParameter | `BaseColor` | (0.165,0.176,0.204) | 只喂五色调色板的值 |
| ScalarParameter | `EmissiveMask` | 0.0 | L3 预警 / L4 玩家色的发光强度 |
| ScalarParameter | `Roughness` | 0.85 | 平涂用高粗糙度，避免高光抢注意力 |
| ScalarParameter | `HeightReadAmount` | 1.0 | 高度可读性效果强度，0 = 关闭 |
| StaticSwitchParameter | `bIsStructure` | false | **全项目唯一允许的 Static Switch** |

> **为什么只允许 1 个 Static Switch**：每加一个 Switch，shader 排列数翻倍。现在 14 个材质感觉无所谓，等你导入 100+ 件素材后，3 个 Switch 就是 8 倍排列，编译时间会变成日常开发摩擦。

### C4. 接入 MF_HeightReadability

1. 右键搜索 `MaterialFunctionCall`，放一个
2. Details 面板的 `Material Function` 选 `MF_HeightReadability`
3. 它的 `LayerStep` 输入接一个 Constant，值填 **650**
4. `GroundZ` 接 Constant，值 0（后续可按关卡改）

连线：

```
BaseColor (VectorParameter)
    ↓
Add ← HeightBand（来自 MF）
    ↓
Multiply ← ContactShade（来自 MF）
    ↓
Lerp ← LayerLine 作为 Alpha，B 端接稍亮的颜色
    ↓
→ 接到材质节点的 Base Color 引脚

Roughness (ScalarParameter) → 接 Roughness 引脚

BaseColor × EmissiveMask → 接 Emissive Color 引脚
```

### C5. 检查指令数（这一步别跳过）

Apply → Save，然后看左下 **Stats** 面板：

| 指标 | 门槛 | 超了怎么办 |
|---|---|---|
| Base Pass Instructions | **≤ 180** | 检查是否误加了多余节点 |
| Texture Samples | **≤ 4**（目标 1） | 平涂不该有贴图，超了说明接错了 |

俯视 low-poly 平涂如果超过 180 指令，一定是哪里做多了。

| MI 名称 | BaseColor (Hex) | Linear RGB | EmissiveMask | 用途 |

> UE 的 Vector Parameter 用**线性空间**数值，不是 sRGB 的 0-255。上表已经换算好了，直接填 Linear RGB 那一列。
>
> 如果你想自己核对：在颜色选择器里可以直接粘贴 Hex，UE 会自动转换。

### D3. 三条不能破的纪律

1. **地面永远最暗。** `MI_Ground` 明度锁在 18% 附近，硬上限 22%。这样任何在空中或高处的物体都天然从背景浮出来，不需要描边就有剪影分离。

2. **威胁色用橙（`#FF7A1A`）对青（`#22D3EE`），不用红对绿。** 在红绿色盲（protanopia / deuteranopia）下，这两色仍保留约 8% 明度差 + 明确的冷暖分离，色盲玩家可辨。这一条直接满足你工时表里那 1 小时「威胁色走色盲安全方案」。

3. **青色是玩家专属频道。** 屏幕上任何青色物体都表示「这是你造成的 / 你能控制的」。这条规则一旦破坏——比如给某个敌人也用了青色——整套视觉语言就废了。

### E1. 在第一张关卡建

# 常见问题

**Q：改完画面变丑了，是不是弄错了？**

第一批做完画面必然变暗变平，因为曝光改手动了但后处理体积还没建。走完第二批的步骤 E 才是完整状态。**不要在第一批结束时判断成败。**

**Q：控制台输入命令没反应？**

确认是按 `~` 键（数字 1 左边那个）打开的控制台，且输入时**不带 `=` 和数值**。只输入 `r.RayTracing` 回车，它会显示当前值。

**Q：shader 编译很久还没完？**

工程只有 14 个材质，正常 5–10 分钟。如果超过 20 分钟，看看右下角进度条是不是卡住了；可以关掉编辑器删掉 `Vector/Saved/ShaderDebugInfo` 和 `Vector/DerivedDataCache` 再重启（这会重编但更干净）。

**Q：Material Function 里找不到某个节点？**

图表空白处右键会出现搜索框，直接打节点名。UE 的节点名都是英文，比如 `Frac`、`Floor`、`SmoothStep`、`Saturate`、`OneMinus`。

**Q：MI 的颜色填进去和我想的不一样？**

UE 的 Vector Parameter 是线性空间。用表格里的 Linear RGB 列，或者点开颜色选择器直接粘 Hex 值让 UE 自己转。

**Q：第二批能不能跳过一部分？**

步骤 A/B/C/D（材质体系）**不能跳**——它是导入 100+ 件素材前的必要前置，不然素材各自带材质，统一 Lookdev 就做不成了。

步骤 E（后处理）不跳的话画面才算完整。步骤 F（命名）可以晚点做，但要在大批导入前完成。
