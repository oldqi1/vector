## 1. 盘点范围与方法

- **源码范围**：`Morphorbit/Source/` 全部 42 个文件（24 .cpp + 18 .h，约 9.5k 行），以及 `Morphorbit.uproject`、`Config/*.ini`、`Morphorbit.Target.cs` / `MorphorbitEditor.Target.cs`。

  - **A 类**：不依赖球面/径向重力的独立逻辑，可原样或近原样移植（改名 + 去 Morphorbit 专属类型引用）。

- **映射基线**：新项目统一物理接口六环节（施力 → 修改属性 → 建立约束 → 处理碰撞 → 触发反应 → 恢复稳定），下文每项标注映射环节。

## 3. A 类资产清单（可原样 / 近原样移植）

> 改造点均不含球面数学；移植时仅需改类名前缀与所属模块 API 宏。

### A1 稳定值 / 失衡核心数值与结算 —— ★最高优先
- **源文件**：`Morphorbit/Source/Morphorbit/Private/Threats/MorphorbitBackjetBeast.cpp`（L21-28 常量区；L975-1035 `ResolveWeakpointHit`）
- **资产**：
  - `MaximumStability = 60.0`、`MinimumBaseStaggerDamage = 20.0`、`MaximumBaseStaggerDamage = 30.0`、`WeakpointStaggerMultiplier = 1.5`
  - 稳定度扣减 → 归零重置到 60 → `bTriggeredStagger` → 进入 `Staggered` Recovery（≥1.60 s）
- **可移植性**：数值与"归零 → 失衡"状态迁移完全独立于球面，可直接作为新项目**稳定 → 失衡 → 倒地**状态机的初始账本。
- **改造点**：常量/逻辑抽到独立组件（如 `UStabilityComponent`），去掉对 `AMorphorbitBackjetBeast` 动作阶段的耦合；失衡后的"倒地表现/起身计时"由新状态机接管。
- **映射环节**：恢复稳定（六环节之六）。

### A2 稳定度夹具合同（可破坏目标）
- **源文件**：`Combat/MorphorbitImpactBladeTarget.h/.cpp`
- **资产**：`ReceiveImpactBladeHit(ClosingSpeed, ImpactPoint, ImpactNormal, SweepDirection) → 20-30 失衡量`；`ResetFixture()` 恢复 60 稳定度；规则碰撞体与视觉后坐分离（WeakPointMesh vs ReactionVisual）。
- **可移植性**：纯平面合同，唯一球面无关项是 `WorldImpactNormal`（平面中取水平法向即可）。
- **改造点**：更名（如 `VectorStabilityTarget`）；接入新碰撞伤害公式（相对速度 × 质量系数 × 碰撞类型系数）。
- **映射环节**：处理碰撞 + 恢复稳定。

### A3 闭合速度 → 失衡量映射（碰撞伤害计算）
- **源文件**：`Combat/MorphorbitImpactBladeComponent.h/.cpp` 静态函数 `ComputeClosingSpeedCmPerSecond`、`ComputeStaggerDamage`
- **资产**：正向切向闭合速度（截断 [0, 300] cm/s）→ 线性映射 [20, 30] 失衡量；无效/非闭合输入返回零。
- **可移植性**：纯静态函数，零 World 依赖，可直接复制。
- **改造点**：把"闭合速度 → 失衡量"升级为新公式 `相对速度 × 质量系数 × 碰撞类型系数`；质量系数是新项目三档（轻/中/重）的新增输入。
- **映射环节**：处理碰撞。

### A4 受控冲量队列（施力核心）—— ★最高优先
- **源文件**：`Gravity/MorphorbitCharacterMovementComponent.h/.cpp`（`QueueWorldVelocityChange`、`ClearQueuedWorldVelocityChanges`、`CalcVelocity` 消费、`PhysWalking` 1/120 s 子步）
- **资产**：排队一次性世界空间 Δv，在下一帧正常 `CalcVelocity` 之后消费；子步化保证高速冲量不穿墙；`StopMovementImmediately` 时清空。
- **可移植性**：**完全平面可用**——该机制不读写径向重力，只是"把 Δv 注入 CharacterMovement"。唯一球面依赖是 `TickComponent` 里的 `RefreshRadialGravity()`（C 类，移植时删除）。
- **改造点**：抽为 `UVectorImpulseReceiver`/独立 MovementComponent 子类；冲量锤/引力钩/升空叉统一走此入口（符合基线"装备 = 意图声明"）。
- **映射环节**：施力（六环节之一）。

### A5 撞脊 / 高速碰撞判定
- **源文件**：`Threats/MorphorbitRingHunter.cpp`（L161-191 `IsValidRidgeImpact`）；`Threats/MorphorbitBackjetBeast.cpp`（L950-973）
- **资产**：`-Dot(VelocityDirection, ImpactNormal) ≥ 0.65` 且速度 ≥ 720 cm/s → 判定"撞脊"（本工程语义：高速正面撞硬表面触发过热/长恢复）。
- **可移植性**：**零球面依赖**的纯几何判定，可直接移植为"撞墙爆发/落地震荡"的碰撞类型分类。
- **改造点**：阈值改可配 UPROPERTY；速度/入射阈值对应新碰撞类型系数。
- **映射环节**：触发反应。

### A6 玩家受击 = 伤害 + 一次性冲量（碰撞连锁样例）
- **源文件**：`Threats/MorphorbitBackjetBeastEncounter.cpp`（`ResolvePlayerPounceHit` / `ResolvePlayerBackpressureVentHit`）
- **资产**：合法命中扣核心伤害（30/20），并在同一结算点 `QueueWorldVelocityChange(Δv 3400/1800 cm/s)`——"被打飞"的完整结算模式。
- **可移植性**：结算模式与平面一致；命中方向从"球面切向"改为"水平面受击方向"即可。
- **改造点**：伤害入口统一为基线"处理碰撞"单一入口。
- **映射环节**：处理碰撞 + 施力。

### A7 调试诊断工具
- **源文件**：`Diagnostics/MorphorbitMovementDiagnostics.h/.cpp`；`Diagnostics/MorphorbitAssetRepairLibrary.h/.cpp`
- **资产**：`ComputeTangentSpeedCmPerSecond`（速度投影到切平面 → 平面中即水平速度）；`BuildScreenText`（单行诊断文本）；资产 Socket 修复库（Editor 脚本）。
- **可移植性**：纯函数 + 无 World 依赖；`AssetRepairLibrary` 可直接复用。
- **改造点**：切线速度改为水平 XY 速度；诊断开关（F1）模式沿用到新工程。
- **映射环节**：工程基础设施。

### A8 输入抽象（Enhanced Input 运行时构造）
- **源文件**：`Input/MorphorbitTangentInput.h/.cpp`；`Gravity/MorphorbitGravityCharacter.cpp` L994-1082 `EnsureRuntimeMoveInput` / `InstallRuntimeMoveInputContext`
- **资产**：`TryBuildWorldInput(LocalUp, ViewForward, ViewRight, MoveInput, OutWorldInput)`（镜头相对 WASD → 世界方向）；运行时 `NewObject<UInputAction>` + `UInputMappingContext::MapKey` + Modifier 链（Negate/Swizzle/Scalar）模式。
- **可移植性**：运行时构造模式已在新工程骨架直接采用（`VectorCharacter::EnsureRuntimeInput`）；`TryBuildWorldInput` 平面化后 `LocalUp = Z`。
- **改造点**：无（新骨架已含 Move/Look）。
- **映射环节**：工程基础设施。

### A9 动作时间线纯函数账本
- **源文件**：`Combat/MorphorbitRecoilCannonComponent.h/.cpp`（`FMorphorbitRecoilCannonTimeline`、`TryStartTimeline`、`AdvanceTimeline`）
- **资产**：Idle → Charging → Recovery 单向时间线，长帧跨越边界只触发一次开火；**零 World 依赖**，运行时与 Automation 共用同一账本。
- **可移植性**：可直接复用为任何"蓄力-释放-恢复"装备（冲量锤蓄力即是此形态）。
- **改造点**：更名，保留结构。
- **映射环节**：施力（装备动作阶段）。

### A10 测试模式（验证驱动开发基座）
- **源文件**：`Private/Tests/` 16 个 `WITH_DEV_AUTOMATION_TESTS` 测试文件
- **资产**：纯函数/纯解算器与运行时分离 → 无 World 可测；测试断言风格（确定性参数、真实 World 双路径）。
- **可移植性**：方法论直接沿用；新工程首个 Story 应先移植 A1/A3 的纯函数并配测试。
- **改造点**：重建新工程的测试文件（复制模式，不复制球面用例）。
- **映射环节**：工程基础设施。

## 8A. 移植红线：两条原项目架构债务的处置（2026-08-13 主理人+用户确认）

> 用户指出 Morphorbit 的两条架构债务（DEBT-01/02），已做源码级验证——**两条均仍存在**。新项目移植必须区别处置，不得照搬旧结构。

### DEBT-02：局部朝上计算分散（4+ 处）——平面化后自然消解，禁止移植相关抽象

**原项目现状（源码证据）**：
- `MonowheelMovementComponent.cpp` 6+ 处独立计算 `LocalUp`，来源不统一：`SurfaceUp.GetSafeNormal()`（参数传入）与 `-GetGravityDirection()`（自算）并存；
- `BackjetBeast.cpp` L1041/L1170 走 `GetActorUpVector()` 读缓存，与径向重算路径并存，无断言保证同步；
- 相机/输入/瞄准表现各自再 `GetSafeNormal()` 消费，无单一权威源。

**新项目处置（红线）**：

## 13. 动量模型修正（2026-08-13，用户反馈"重物也飞很远"）

- 旧模型（错误）：质量是"速度系数"（PushFactor 轻1.0/中0.6/重0.35 直接乘速度）→ 重物 420 cm/s，推不动感不足。
- **新模型（动量定理）**：冲量锤施加固定冲量 I = ImpulseSpeed(1750) × Charge，目标速度变化 **Δv = I ÷ 相对质量**；质量档：轻 1.25 / 中 2.5 / 重 5.0。
- **UE 制动公式验证（引擎源码 ApplyVelocityBraking L4417）**：`Velocity = Velocity + ((-Friction)·Velocity + RevAccel)·dt`——指数摩擦（×速度）×线性制动混合，且 `BrakingFrictionFactor` 默认 2.0。旧参数下（0.6/200）实际制动 a(v)=1.2v+200，**高速急停**：中 720→3.7m、重 420→1.75m（仅 2.1 倍差距）——用户观察准确。
- **修正后参数（精确解）**：靶子 GroundFriction=1.0、BrakingFrictionFactor=0.5、BrakingDeceleration=400 → a(v)=0.5v+400：
  - 轻 Δv1400 → **~12m**（弹药，飞出竞技场）
  - 中 Δv700 → **~4m**（可连锁）
  - 重 Δv350 → **~1.2m**（推不动，需润滑/侧击/借力）
  - 距离比 ≈ 10:3:1，物理可感知。
- 改动：VectorImpulseHammerComponent（MassValue 表 + I/m 公式）、VectorTestDummy（制动 0.5/400）。
- 注意：UPROPERTY 字段名变更（PushFactor→MassValue）→ **需完整编译 + 重启编辑器**。
