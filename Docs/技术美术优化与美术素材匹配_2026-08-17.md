## 0. 一句话结论

**当前渲染配置在为一个「不存在的写实项目」付费。**

工程开启了 Substrate、RayTracing、Lumen GI、Lumen Reflection 四项重型特性，而 Content 里实际只有 **27 个 uasset、14 个纯色三色材质、零贴图、零 Niagara、零后处理体积**。这不是「画面还不够好」，而是**渲染预算 100% 花在了俯视 low-poly 平涂看不见的地方，同时一分钱没花在这个项目真正需要的东西上——落点、高度、结构状态的可读性。**

更严重的是：其中两项**主动伤害**你已写进红线的可读性目标（见 §1.2、§1.3）。

### 1.2 A1/A2 光线追踪 —— 物理游戏的隐形性能税（最高优先）

这不是「用不上所以浪费」那么简单，而是**成本随你的核心玩法线性增长**。

`r.RayTracing=True` 会为场景构建并维护 BVH（加速结构）。BVH 对静态几何是一次性成本，但**对每一个位置或形变发生变化的物体，都要在该帧重建或刷新其条目**。

而这个项目是什么？

- 矢量枪注入速度的刚体
- 实体动能球
- 双端绳线约束下摆荡的目标
- 升空叉抛起的空中目标
- 落地震荡推开的碎块
- Boss 布娃娃

**全场几乎所有值钱的东西都在动。** 你的核心玩法恰好命中 RayTracing 最差的输入分布：高动态刚体密度。战斗越激烈、物理交互越多——也就是你最需要帧率稳定的那一刻——BVH 刷新成本越高。这是一条与玩法正相关的性能反向曲线。

同时 `RayTracingProxies` 会为网格额外生成并常驻代理数据，增加内存与 cook 时间。

而收益是多少？俯视视角、三色平涂无贴图、无镜面材质、无玻璃、无水面。**RT 反射与 RT 阴影在这个画面上产生的可见差异接近零。**

> 判定：**关闭。这是纯负收益项，不是主观风格选择。**

### 1.3 A3 Substrate —— 为空图集付 shader 税

`r.Substrate=True`（:23）启用 UE5 的多层材质系统，把 GBuffer 与材质求值切到 Substrate 路径。它的价值在于分层材质：湿滑涂层叠泥土叠岩石、多层清漆、复杂次表面。

你的材质是什么？`Main.uasset` / `Black.uasset` / `Belly.uasset` / `Eyes.uasset` / `Nose.uasset`——**Quaternius 三色平涂，无 BaseColor 贴图、无 Normal、无 Roughness map。**

Substrate 在这里的实际效果：
- 每个材质的 shader 排列与编译时间上升
- GBuffer 布局变化（`ProjectGBufferFormat=0`），基础通道成本增加
- 视觉差异：**0**

额外风险：Substrate 仍在演进，第三方 CC0/Fab 素材包的材质普遍针对**旧 Shading Model** 编写。你后续导入 Kenney / Quaternius / Niagara Examples 时，Substrate 开启状态下的材质迁移会出现不一致，需要逐个返修——这正是你在采购评估文档 §4 里已经写明要规避的「材质引用外部 Substrate/自定义节点」风险，只不过风险来自你自己的工程设置。

> 判定：**关闭。** 项目美术路线已定为「风格化 low-poly + 统一渲染层，不做写实高模」，Substrate 与该路线在需求上无交集。

### 1.4 A4/A5/A11 全局光照与阴影 —— 这里直接撞可读性红线

这一条是本次诊断中**最需要你亲自裁决**的，因为它不只是性能问题。

你的 P0 红线是：**地面投影影子、高度垂线刻度、落点预测环——未落地前不得投产垂直机制。**

Lumen 的工作方式与这条红线冲突：

| Lumen 特性 | 对本项目的后果 |
|---|---|
| 屏幕空间追踪 + 时间累积 | 快速移动的**空中目标**（升空叉抛起、19.1m 弹道）在间接光里出现拖影与延迟收敛 |
| Surface Cache 更新有延迟 | 高速刚体的间接光贴不上，视觉滞后于物理 |
| Lumen Reflection（`ReflectionMethod=1`） | 平涂无镜面材质，反射贡献≈0，纯成本 |
| 与 TSR 叠加 | 小尺寸高速物体（动能球、碎块）被时间抗锯齿糊掉边缘 |

**你要玩家读懂的正是这些高速小物体的落点。Lumen + TSR 恰好让它们变糊。**

而 Virtual Shadow Maps（`r.Shadow.Virtual.Enable=1`）在这里是**两难**：VSM 精度高，但对大量动态物体的页面缓存失效频繁；而俯视游戏的阴影承担的是**功能职责**（判断物体在地面的哪个位置），不是氛围职责。

> 我的专业建议（但风格方向由你决定）：
>
> - **A5 Lumen Reflection：直接关闭**（这一项无争议，零收益）
> - **A4 Lumen GI：降级为 SSGI 或关闭 + 手工三点光**——理由是「可控性 > 真实性」。俯视 low-poly 用一盏方向光 + SkyLight + 一盏补光就能得到干净可读的明度分层，且**完全确定**，不会因为相机移动而变化。
> - **A11 VSM：保留，但阴影的可读性职责改由独立的投影系统承担**（见 §2.3）——不要指望渲染阴影同时兼顾氛围和落点判读，那是两个需求。

### 1.5 A10 MeshDistanceFields —— 保留（有明确用途）

`r.GenerateMeshDistanceFields=True` 通常是为 Lumen / DFAO 服务，关掉 Lumen 后本可关闭以省内存。**但建议保留**，原因是 Niagara 的 **Distance Field Collision** 依赖它。你的 VFX 需求（撞击碎屑、落地震荡尘环、碎块沿地面滑散）用 DF 碰撞比逐粒子物理碰撞便宜一个数量级——这正是 Niagara 规范里「GPU 系统避免逐粒子碰撞」的推荐替代方案。

### 1.6 A6 Niagara 未启用 —— 硬阻塞

`Vector.uproject` 的 `Plugins` 数组**只有 `ModelingToolsEditorMode` 一项**。Niagara 虽为引擎内置，但你的美术工时表里排了 2.5h「Niagara：矢量枪弹道、绳线、动能球撞击」——**当前工程状态下这 2.5h 无法开始**。同时 Fab 上的 Niagara Examples Pack 也依赖插件启用。

这是排期上的一个真实前置缺口，建议立刻补。

### 1.7 A7 缺 Scalability 配置

`Config/` 目录下只有 4 个 ini，**没有 `DefaultScalability.ini`**。后果：

- 无法定义 Low / Medium / High 预设
- Niagara 的可扩展性分组失去项目级基线
- 打包后玩家无有效画质档位
- 你的 RTX 4070 笔记本上「跑得动」不代表试玩者跑得动，而这是**定向机制验证包**，帧率崩了会被误判为手感问题

## 2. Phase B — 预算搬迁：把钱花在可读性上

关掉 RT / Substrate / Lumen Reflection 省下的预算，全部投向三个方向。**这三项才是「成熟感」的真实来源。**

### 2.1 五色调色板（明度锁定 + 色盲安全）

俯视视角下，玩家 90% 的信息来自**剪影与明度**，不是色相。所以调色板必须先锁明度，再定色相。

| 层 | 用途 | 色值 | 明度 L* | 纪律 |
|---|---|---|---|---|
| L0 底 | 地面、远景、非交互结构 | `#2A2D34` | ~18% | **任何时候不得超过 22%** |
| L1 中 | 可破坏结构、掩体、锚点 | `#5A6069` | ~40% | 结构完好态 |
| L2 主 | 敌人主体、怪物躯干 | `#D96E3B` | ~55% | 必须高于地面 2 档 |
| L3 警 | 威胁预警、弱点、Boss 井口 | `#FF7A1A` | ~68% | 仅用于「现在要处理」 |
| L4 玩家 | 矢量线、绳线、落点环、工具 | `#22D3EE` | ~76% | **玩家意图专属，敌人绝不使用** |

关键纪律三条：

1. **地面永远最暗。** 明度压到 18% 附近，任何在空中或高处的物体天然从背景里浮出来——不需要描边就有剪影分离。
2. **威胁色用橙（L3）对青（L4），不用红对绿。** 在 protanopia / deuteranopia 下，`#FF7A1A` 与 `#22D3EE` 仍保留约 8% 明度差 + 明确冷暖分离，色盲玩家可辨。这直接满足你工时表里那 1h「威胁色走色盲安全方案」。
3. **L4 是玩家的专属频道。** 屏幕上任何青色物体都表示「这是你造成的 / 你可以控制的」。这条规则一旦破坏（比如给某个敌人也用青色），整套视觉语言就废了。

### 2.2 Master Material 架构（当前完全缺失）

现状：14 个散装材质直接躺在 `Content/Vector/Art/PrototypeMonsters/*/`，命名为 `Main` / `Black` / `Eyes` / `Belly` / `Nose`，**无 `M_` 前缀、无 Master、无 Material Instance、无 Material Function**。

后续要导入 Kenney（40 件）+ Quaternius Sci-Fi（60+ 件），如果不先建立体系，就会变成 100+ 个散装材质——那是不可能做统一 Lookdev 的。

**必须先建，再导入。顺序不能反。**

```
M_VectorMaster                          （唯一主材质，Unlit 或极简 DefaultLit）
├── Param: BaseColor        (Vector)     ← 只喂 §2.1 五色
├── Param: EmissiveMask     (Scalar)     ← L3/L4 发光强度
├── Param: HeightFogAmount  (Scalar)     ← 见 §2.3
├── Switch: bIsStructure    (Static)     ← 唯一允许的 Static Switch
└── MF_HeightReadability                 （Material Function，见下）

MI 派生：
  MI_Ground / MI_Structure / MI_Structure_Broken
  MI_Enemy_Light / MI_Enemy_Heavy / MI_Enemy_Weakpoint
  MI_Tool_VectorGun / MI_Tool_Rope / MI_Boss_Shell
```

**Static Switch 只允许一个。** 每增加一个 Static Switch，shader 排列数翻倍。当前你有 14 个材质，感觉无所谓；导入 100 件素材后，3 个 Switch 就是 8 倍排列，编译时间会变成开发摩擦。

指令数预算（Material Stats 窗口读取）：
- 主材质 Base Pass **≤ 180 指令**（low-poly 平涂，超过说明做错了）
- 纹理采样 **≤ 4**（目标是 1：单图集）
- 全项目单图集单材质，俯视看不见细节，多材质纯亏 DrawCall

### 2.3 MF_HeightReadability —— 直接服务 3D 核心判据的 Material Function

这是本方案里**唯一为你的七项量化判据专门设计的技术件**。你的判据要求「玩家必须读懂落点，并能主动制造或改变高度关系」——那么高度必须在材质层被编码成可见信号。

```
Material Function: MF_HeightReadability

输入:
  GroundZ        (Scalar)  — 当前区域地面基准高度
  LayerStep      (Scalar)  — PCG 层间落差，本项目 = 650 (cm)
  FogTint        (Vector)  — 建议 L0 色 #2A2D34

实现:
  AbsoluteWorldPosition.B → 减 GroundZ → 得 RelativeHeight
  RelativeHeight / LayerStep → Frac → 得层内归一化高度 t
  RelativeHeight / LayerStep → Floor → 得层序号 n

  输出 1  HeightBand    = n              → 驱动每层轻微色偏（每层明度 +4%）
  输出 2  ContactShade  = 1 - saturate(t * 3)
                                         → 贴近地面处压暗，制造接触感
  输出 3  LayerLine     = smoothstep(0.96, 1.0, t)
                                         → 层交界处一道细亮线，让落差「有刻度」

用途: 地面与结构材质。让 650cm 的层间落差在画面上可数，
      而不是靠玩家猜。
成本: 无纹理采样，约 12 指令。
```

**为什么这个比 Lumen 值钱**：Lumen 给你物理正确的间接光，但玩家读不出「这里比我高一层」。`MF_HeightReadability` 给你的是**可数的高度刻度**——这是七项判据里第 1、6、7 项能否成立的视觉前提。

### 2.4 影子系统（不要用渲染阴影）

设计文档已定：**向下 LineTrace + Unlit translucent SDF 圆 Quad，不用 CSM 动态阴影。** 这个决策是对的，补充三条实施规格：

| 项 | 规格 | 理由 |
|---|---|---|
| 半径映射 | `R = BaseR * (1 + h/1200)` | 越高影子越大，给出高度量感 |
| 不透明度 | `A = 0.55 * (1 - saturate(h/1600))` | 越高越淡，但**保留下限 0.12**，不许完全消失 |
| 颜色 | L0 色 × 0.6，**不用纯黑** | 纯黑影子在 18% 明度地面上会糊成一团 |
| 边缘 | SDF 圆，`smoothstep(0.42, 0.5, dist)` | 软边比硬边更容易读中心点 |

**下限 0.12 是关键。** 影子完全消失的那一刻，玩家就丢失了空中目标的落点信息——而那恰好是你最需要他读懂的时刻（19.1m 高抛）。

### 2.5 后处理体积（6 张关卡全部缺失）

`L_Prototype01~05` + `L_AimPreviewTest` **一个 PostProcessVolume 都没有**。这意味着 6 张关卡的画面完全依赖引擎默认值，且**互不一致**——你没法在这种状态下评估「风格统一」。

统一基线（建议建成一个 Blueprint 或 Level Instance 复用到 6 张图）：

```
PostProcessVolume  (Unbound = true, Priority = 0)

曝光    AutoExposure Method: Manual        ← 关键，见下
       ExposureCompensation: 1.0
Bloom  Intensity: 0.35   Threshold: 1.2   ← 只让 L3/L4 发光溢出
色彩    Saturation: 1.08  Contrast: 1.12
       Shadows Gain: 0.92（压暗地面）
       Highlights Gain: 1.05
AO     Intensity: 0.45   Radius: 90       ← 短半径，只做接触阴影
运动模糊 MotionBlurAmount: 0.0             ← 必须为 0
胶片颗粒 0.0
晕影    Intensity: 0.25
```

两条硬性理由：

1. **曝光必须 Manual。** 当前 `r.DefaultFeature.AutoExposure.ExtendDefaultLuminanceRange=True`（:27）配合自动曝光，会在玩家进出明暗区域时改变整屏明度——**这会直接破坏 §2.1 的明度分层纪律**。地面必须永远是 18%，不能因为镜头转向而变成 30%。
2. **MotionBlur 必须为 0。** 你要玩家读高速物体的运动方向与落点，动态模糊在做完全相反的事。这不是风格偏好，是功能冲突。

## 4. Phase D — 美术素材匹配

### 4.1 风格锚点：你的风格已经被现有资产定死了

`ArtSource/QuaterniusAnimatedMonsterPack`（CC0 1.0）已经进了工程，4 只怪物（Bat / Skeleton / Slime / Dragon）已映射为轻型跳跃怪 / 冲锋怪 / 四锚重型 / 磁壳 Boss。

这意味着风格锚点**不是待定项，而是已定项**：Quaternius 的 flat-color low-poly。

因此素材匹配的第一原则不是「找好看的」，而是**「找和 Quaternius 同一套视觉语法的」**。具体是四条可核验的一致性指标：

| 指标 | Quaternius 特征 | 混搭风险 |
|---|---|---|
| 贴图策略 | 无贴图，纯顶点色 / 纯色材质槽 | 一旦混入 PBR 贴图资产，同屏就会出现「一半有细节一半没有」 |
| 多边形密度 | 数百至约 2000 三角面 | 混入 Nanite 高模，剪影密度不一致 |
| 造型语法 | 硬边、大块面、无倒角细节 | 混入圆滑写实模型立刻出戏 |
| 色彩逻辑 | 中高明度、低到中饱和 | 混入高饱和卡通色会抢掉 L3 威胁色的注意力 |

### 4.2 推荐清单（按优先级，全部 CC0 / 免费）

#### P0 — 立刻做，零成本，收益最高

**① 重下 Quaternius Animated Monster Pack 的 FBX 版本**

这不是新素材，是**修复你已有素材的导入路径**。

已核实事实：
- 官方 `quaternius.com/packs/animatedmonster.html` 提供 **FBX + OBJ + Blend 三格式，4 只怪物各自带动画**
- 本地 `ArtSource/QuaterniusAnimatedMonsterPack/` **只有 `.obj` + `.mtl`，缺 FBX**
- `Tools/Art/import_prototype_monsters.py` 硬编码 `.obj`、`import_as_skeletal=False`、`FBXIT_STATIC_MESH`
- 结果：4 只怪物在引擎内是 `SM_Prototype_*` 静态网格，**零动画**

**「怪物没动画」是导入配置问题，不是资源缺失问题。** 修复约 1.5–2.5h，收益是 4 只怪物全部拿到骨骼与动画，成本 0 元。在 30 小时预算下这是单位时间回报最高的一步。

**② Niagara Examples Pack（Epic 官方，Fab，免费）**

已核实：Epic 于 2026 年 1 月在 Fab 发布首版，**50+ 个 Niagara 系统**，含爆炸、弹道撞击、火花、拖尾、烟雾、闪电、受击消散、ping / 标记，附一张 gallery 演示关卡。每个系统已指定 Niagara Effect Type 与可扩展性设置（生成上限、远距离暂停/终止、各档生成倍率）。含基于 **Niagara Data Channel** 的撞击 / 脚步系统——用单个系统处理整片区域的所有撞击，大幅减少组件数。

对本项目的直接价值：
- **弹道撞击 → 矢量枪命中**
- **爆炸 / 冲击波 → 落地震荡**
- **拖尾 → 动能球、绳线**
- **受击消散 → 结构破坏**

它还顺带解决 §1.7 的问题：官方系统自带的 Effect Type 与可扩展性分组，可以直接作为你 `DefaultScalability.ini` 的参照基线，而不用凭空拍数值。

> ⚠️ 版本注意：官方标注为 **UE 5.7**，你的工程是 **5.8**。导入后需验证 Niagara 模块无 deprecation 警告。同时**先关 Substrate 再导入**（§1.3），否则材质路径不一致。

**③ 后处理 + 调色板 + Master Material（自制，约 3h）**

这部分买不到，必须自己做。见 §2.1 / §2.2 / §2.5。

采购评估文档里的结论在这里再确认一次：**「成熟」与否约八成取决于 Lookdev 与 VFX，那是必须自己做的部分。** 采购只能替你跳过从零建模，而那一步你已经免费跳过了。

### 4.4 导入纪律（导入前必须先满足）

顺序不可颠倒，否则要返工：

1. **先关 Substrate**（§1.3）—— 否则第三方材质路径不一致
2. **先启用 Niagara**（§1.6）—— 否则 VFX 包无法导入
3. **先建 M_VectorMaster + 五色 MI**（§2.2）—— 否则 100+ 件素材各自带材质，无法统一 Lookdev
4. **统一单位**：Quaternius 常见 0.01 缩放，OBJ 导入用了 100.0，**FBX 需实测确认**；目标 1uu = 1cm、Z-up、Scale 1.0
5. **Root Motion 全部关闭** —— 本项目移动由物理驱动
6. **命名前缀**：`SM_` / `SK_` / `M_` / `MI_` / `NS_` / `T_`，导入后立即审计（现有 `Main` / `Black` / `Eyes` 等 14 个材质需一并改名）
7. **PhysicsAsset 必须实测可用** —— 物理 Boss 要吃布娃娃与约束，这是本项目最特殊的硬门槛

## 7. 需要你裁决的三个问题

前两项是纯技术错误，我建议直接执行；**只有这三项属于风格方向，不替你拍板**：

1. **Lumen GI 去留（§1.4 A4）** —— 关掉换手工三点光（可控、确定、便宜、保护明度纪律），还是保留 Lumen 接受空中高速目标的间接光滞后？我倾向关掉，但这会让画面「不那么现代」，是可见的风格取舍。
2. **抗锯齿 TSR → FXAA（§3）** —— FXAA 保住小物体边缘清晰（利于读落点），代价是静态画面边缘不如 TSR 干净。俯视快节奏下我认为值，但你可能更在意静帧观感。
3. **UI kit 是否掏钱（§4.2 ⑦，$15–25）** —— 唯一还值得花钱的项。若 §2.1 调色板落地，自绘也能达标。
