# 冲量与生命显示修复验收（2026-08-14）

## 0. 编译前提

- 本次新增 `AVectorHUD` UCLASS、动态委托与多项 UPROPERTY；关闭 Unreal Editor 后执行一次完整 `VectorEditor / Win64 / Development` 编译，再重启编辑器。
- 若 VS 中没有显示 `VectorHUD.h/.cpp`，可重新生成项目文件；UBT 正常情况下仍会自动发现源文件。
- 编译成功后，地图的 GameMode 必须是 `VectorGameMode`（它负责设置 `HUDClass=VectorHUD`）。

## 1. Automation 回归

在 Session Frontend → Automation 搜索并运行：

- `Vector.Impact.CollisionSolve`：3 项全部 Success；
- `Vector.Impact.ComputeCollisionDamage`：3 项全部 Success；
- `Vector.Health`：全部 Success；
- 最后搜索 `Vector.` 跑全套。

成功标准：零 Failed；尤其 `EqualMassConservation` 必须确认撞击者碰后为正向 15%、目标为正向 85%、总动能不增加。

## 2. 等质量怪物互撞（原反向高速弹回问题）

场景：两只 Light 怪或 Light 测试靶沿攻击方向排成直线，间距约 1–2m；满蓄锤击前方第一只。

成功表现：

- 第一只撞上第二只后明显减速，但仍小幅向前，不以接近原速度高速反弹；
- 第二只向前飞出形成连锁；
- Output Log 出现 `Collision solve:`，末尾必须是 `check=PASS`；
- 等质量、目标近似静止时，日志 `result=(...)` 约为入射法向速度的 `(15%, 85%)`；
- 不得出现 `Collision invariant failed`。

辅助日志：

- `LogVectorMovement: Velocity override consumed`：显示覆盖前速度、目标速度和真实 Δv；
- `LogVectorImpact: Collision solve`：显示双方质量、碰前/碰后速度、动量和动能；
- `LogVectorImpact: Body collision`：显示闭合速度、伤害及撞击者质量档。

## 3. 质量差碰撞

### 重撞轻

先把 Heavy 打失衡，再推向 Light。

- Heavy 应继续向前，Light 高速飞出；
- Light 的单体速度可能略高于 Heavy 的入射速度，这是质量差碰撞允许的结果；
- 判断正确性的硬标准仍是 `check=PASS`、动量前后近似相同、总动能不增加；
- `Body collision` 必须显示双方质量档与 `damage(target=...,striker=...)`：被撞者伤害采用撞击者质量，撞击者反作用伤害采用被撞者质量；双方速度仍只解算一次。

### 轻撞重

把 Light 推向稳定 Heavy。

- Light 可以低速反弹，这是轻物撞重物的合理结果；
- 反弹速度不得高于入射速度；Heavy 只获得较低速度；
- 日志仍须 `check=PASS`。

## 4. 怪群连续碰撞与重复接触

场景：3–5 只怪紧密排成一列，将第一只满蓄推出。

成功标准：

- 每一段有效碰撞都有独立 `Collision solve ... check=PASS`；
- 速度随连锁总体衰减，不出现同一对怪每帧互相注入越来越大速度；
- 同一对物体完成首次解算后已经分离，后续重复接触应因闭合速度为 0 而被忽略；
- 日志中不得出现 `Collision invariant failed`。

## 5. 相对速度

自动化 `MassAndClosingSpeed` 已覆盖：撞击者 1000、目标同向 800 时闭合速度必须是 200，而不是 1000；双方正在分离时闭合速度必须是 0。

人工观察时，追上一个同向高速移动的怪不应按自身全速造成高伤；Output Log 的 `closing=` 应明显低于 `strikerV` 的长度。

## 6. 玩家血条和敌人血条

进入使用 `VectorGameMode` 的 PIE：

- 玩家左下角显示 `PLAYER 100 / 100`；
- 每只存活敌人头顶显示血条，并随镜头正确投影；
- 满蓄锤击敌人时，其头顶血条至少减少锤击保底伤害；
- 生命比例降低后血条由绿向红变化；敌人死亡销毁后血条同步消失。

若完全没有 HUD，优先检查 World Settings 的 GameMode Override 是否为 `VectorGameMode`。

## 7. 普通敌人扑击玩家

站在怪物 250cm 内等待攻击：

- 怪物先白闪约 0.35s，随后扑击；预警结束后恢复该质量档原色；
- 扑击真实碰到玩家时，玩家血条下降并被物理解算推开；
- 一次扑击只扣一次血，不应同时出现固定伤害和碰撞伤害的双扣；
- 日志顺序应包含：`warmup` → `pounce` → `Impact resolved ... damageable=1` → `Collision solve ... check=PASS` → `Health changed: actor=VectorCharacter...`；
- 玩家静止、默认 800cm/s 扑击附近的参考伤害：Light 约20、Medium 约25、Heavy 约35，实际以 `closing=` 为准。

## 8. 角槌兽冲锋玩家

让 Charger 在约 900cm 内发起冲锋，并正面命中玩家：

- 玩家应扣血并被明显撞飞；不再把玩家误判成墙而只让 Charger 自伤；
- 默认 1600cm/s 命中静止玩家通常触发 50 单次伤害上限；
- `Impact resolved` 中 `hit=VectorCharacter... damageable=1`；
- `Collision solve` 必须 `check=PASS`；随后必须有玩家 `Health changed`。

## 9. 玩家死亡与重生

连续受击直至生命归零：

- 日志先出现玩家生命降到 `0 / 100`，再出现 `Health reset` 与 `Player died -> respawn`；
- 玩家回到出生基准位置、血条回满；
- 死亡事件只触发一次，不得同一帧重复重生。

## 10. 落地震荡回归

先在 Unreal Editor 执行 `Tools/Greybox/setup_landing_shock_test.py`，再点击顶部普通 Play。脚本会放置一个 Z=950 的下落测试靶，以及水平距离 300cm 的地面测试靶：

- 先出现 `Landing shock triggered:`，证明落地速度超过 600cm/s 且入口被触发；
- 随后出现 `Landing shock:`，地面测试靶生命降低；
- 普通跳落不足阈值时不触发；
- 这项验证父类切换 Walking 前缓存的真实下落速度没有被清零。
